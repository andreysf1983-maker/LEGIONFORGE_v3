# LegionForge Developer Kit

**LegionForge** — веб-панель разработчика и автономная Windows-среда для сборки и запуска World of Warcraft Legion **7.3.5.26124**. Цифры в названии проекта нет: `7.3.5.26124` указывается только как версия клиента и целевой сборки.

## Исходники сервера — ваши

Кит **не скачивает** исходники ядра. Вы сами кладёте свои исходники в папку
`server\source` так, чтобы файл `CMakeLists.txt` лежал прямо в ней:

```text
server\source\CMakeLists.txt      <- правильно
server\source\cmake\...
server\source\dep\...
server\source\src\server\...
```

Частая ошибка — распаковать архив во вложенную папку
(`server\source\LegionCore-7.3.5V2\CMakeLists.txt`). Кит это распознаёт и
подскажет перенести содержимое на уровень выше. Если папка пустая, `START.bat`
создаст `server\source` и остановится с понятным сообщением.

Кит никогда не обращается к git-репозиторию исходников (без `clone`, `fetch`,
проверки `origin`). Что он всё-таки делает с вашими исходниками:

- копирует нативные моды из `custom/src/` в `src/server/scripts/Custom/`;
- накладывает `patches/overlay/`. **Перед первой заменой** каждый ваш исходный
  файл, который отличается от версии в overlay, сохраняется в
  `runtime\backups\source-originals\` (с тем же относительным путём);
- применяет две маленькие правки совместимости (Boost 1.86 Asio в `Log.h/.cpp`,
  OpenSSL 3 в баннере `Main.cpp`). Если в ваших исходниках этот код уже другой,
  правка **пропускается с предупреждением**, а сборка не падает. Файлы
  перезаписываются только при реальном изменении, поэтому повторный запуск не
  вызывает полную пересборку.

Git для кита больше не обязателен и не скачивается. Если он есть (`tools\git`
или установленный в системе), CMake встроит ревизию в сборку.

## Главный запуск

Запустите **`START.bat`** из корня проекта.

1. Автоматически находит установленный локально Visual Studio (2022/2019 Community, Pro, Enterprise, BuildTools). Никаких тяжелых скачиваний компилятора не производится!
2. Автоматически скачивает в папку `tools/` всё необходимое в портативном виде:
   - Portable CMake (Kitware x64)
   - Portable Node.js LTS (win-x64)
   - Portable MariaDB Community Server (win-x64)
   - Предсобранный Boost 1.86.0 (msvc-14.3-64) + портативный OpenSSL 3.5 LTS (x64) — без компиляции пакетного менеджера
3. Проверяет ваши исходники в `server/source/` (см. раздел выше).
4. Автоматически копирует уже включённые в проект нативные исходники модов из `custom/src/` в `server/source/src/server/scripts/Custom/`.
5. Накладывает готовый слой `patches/overlay/`: загрузчик модулей, свободный трансмог и оплата BattlePay-магазина Сущностями пробуждения.
6. Предлагает выполнить компиляцию Release x64 в `server/runtime/`, запустить локальную MariaDB, AuthServer и WorldServer, а также веб-панель LegionForge.

Повторный запуск использует уже скачанные архивы и существующие инструменты. Скрипты не используют `winget`, не требуют предварительно установленного Git/CMake/Node.js и используют только ASCII-вывод CMD.

Для прямого запуска панели используйте `START_PANEL.bat` или `arguscore.bin.bat`.

## Остановка всего: `Stop.bat`

**`Stop.bat`** в корне проекта останавливает всё, что запустил кит:

| Порядок | Что | Как |
|---|---|---|
| 1 | WorldServer | просьба закрыться, через 15 с — принудительно |
| 2 | bnetserver / authserver | просьба закрыться, через 10 с — принудительно |
| 3 | Веб-панель (Node.js), сборка (cmake + MSBuild + cl.exe), git и другие инструменты, запущенные скрипты `bootstrap.ps1` | сразу, вместе с дочерними процессами |
| 4 | Portable MariaDB | корректный `mariadb-admin shutdown` (InnoDB сбрасывается на диск), через 30 с — принудительно |

Процесс считается процессом кита, если его `.exe` лежит **внутри папки проекта**
(`tools\...`, `server\runtime\...`) или это другой запущенный `bootstrap.ps1`.
Всё, что вне папки проекта (системная MariaDB, другие Node.js-приложения,
Visual Studio), не трогается.

```bat
Stop.bat           rem аккуратная остановка
Stop.bat /force    rem убить всё сразу, без ожидания
```

Чтобы гарантированно сохранить персонажей онлайн, перед `Stop.bat` введите в
консоли worldserver `.server shutdown 1`. Если сервер запускался «от имени
администратора», запускайте `Stop.bat` так же, иначе Windows не даст его
остановить (кит сообщит об этом явно).

### Если вы обновляете проект из репозитория

Запускатор проверяет целостность своих файлов (`tools/launcher-manifest.sha256`).
Если у вас «смешанные» версии (например, новый `bootstrap.ps1` со старым
`project.json` или наоборот), вы получите явную ошибку:

```text
Launcher files do not match this project version: project.json, tools/bootstrap.ps1 ...
```

Решение: скопируйте из актуальной версии проекта **все** файлы
`project.json`, `START.bat`, `START_PANEL.bat`, `arguscore.bin.bat`, `Stop.bat` и **всю папку
`tools/`** (кроме уже скачанных подпапок `git`, `cmake`, `node`, `mariadb`,
`boost`, `openssl` — они переносимы). Папки `server/`, `cache/`, `runtime/` можно оставить.

Проверка целостности нормализует переводы строк (CRLF → LF) перед хешированием,
поэтому одинаково проходит и для ZIP-архива, и для `git clone` в Git for Windows
с `core.autocrlf=true`.

### Ошибки сборки bnetserver про SOAP (`SOAP_C_UTFSTRING`, `fresponse`, `soap::ctx`...)

Если компиляция `LoginRESTService.cpp` падает с десятками ошибок вида
`error C2065: SOAP_C_UTFSTRING: необъявленный идентификатор` или
`"ctx": не является членом "soap"` — это **не проблема самого gSOAP или
OpenSSL**, а повреждённая или урезанная копия файлов в
`server\source\dep\gsoap` (полный `stdsoap2.h` весит ~150 КБ, `stdsoap2.cpp` —
~590 КБ). Обычная причина — антивирус карантинит `stdsoap2.cpp`/`stdsoap2.h`
из-за «сырых» сокетов, либо копирование исходников прервалось.

`bootstrap.ps1` проверяет `dep/gsoap` перед каждой сборкой (если такой папки в
вашем ядре нет, проверка пропускается). Если файлы повреждены:

- если `server\source` — git-репозиторий и git доступен, кит восстановит
  `dep/gsoap` из локальной истории;
- иначе сборка остановится **до** компиляции с сообщением `dep/gsoap in
  server\source is damaged`. Проверьте карантин антивируса, добавьте исключение
  на папку `server` и заново скопируйте `dep\gsoap` из ваших исходных исходников.

## Портативные C++ зависимости (без vcpkg)

Пакетный менеджер vcpkg полностью удалён из проекта: он тянул сотни пакетов,
требовал MSYS2 и регулярно ломался на удалённых зеркалах. Вместо него `START.bat`
ставит три прямых портативных компонента (версии зафиксированы в
`project.json` → `toolchain.dependencies`):

- **Boost 1.86.0** — официальный предсобранный архив `msvc-14.3-64`
  (тихая установка в `tools/boost`; 1.86 — последняя версия с
  `boost/asio/io_service.hpp`, который требует ядро);
- **OpenSSL 3.5.8 LTS** — портативный ZIP FireDaemon (`tools/openssl/x64`,
  заголовки + `.lib` + DLL, без установщика);
- **Клиент MariaDB** — dev-файлы берутся из уже скачиваемого портативного
  сервера (`tools/mariadb/include`, `tools/mariadb/lib/libmariadb.lib`),
  отдельный Connector/C не нужен.

Если после обновления осталась папка `tools/vcpkg` от прошлой версии — её можно
просто удалить, она больше не используется.

## Первый запуск после обновления структуры

Если до обновления уже существует папка `toolchain/`, ничего удалять вручную не нужно. Bootstrap при первом Prepare переносит найденные папки `git`, `cmake`, `node`, `vs-buildtools`, `mariadb`, `boost` и `openssl` в `tools/`. Кэш загрузок сохраняется.

## Игровая база

При запуске сервера автоматически поднимается portable MariaDB на `127.0.0.1:3307` и создаются пустые базы `legion_auth`, `legion_characters`, `legion_world`, `legion_hotfixes`.

Многогигабайтные игровые SQL-дампы и клиентские data-файлы не должны скачиваться из случайных зеркал. Размещайте проверенные, совместимые с этой ревизией исходников дампы в `database/import/`, затем импортируйте их согласно документации LegionCore-7.3.5V2. Пользовательский SQL храните в `custom/sql`.

## Каталог модов

Веб-панель содержит **каталог модов** с 48+ найденными на GitHub дополнениями для Legion 7.3.5. Моды разделены по категориям:

- NPC Services: Buffer, Enchanter, Beastmaster, All Mounts, Services, Free Professions, Talent Template, Arena Spectator
- Transmog & Cosmetic: Transmogrification, Transmog Plus UI, Morphing Flask, Random Morpher
- PvP: 1v1 Arena, Cross-Faction BG, PvP Titles, Kill Announcer, Arena Spectator
- Progression & Balance: AutoBalance, Solocraft, Solo LFG, Individual XP, Level Up Reward, Progression System
- Economy: AH Bot, Junk to Gold, Black Market AH, Lottery
- Bots: Playerbots, NPCBot Extended, Trinity-Bots
- Anti-cheat & Security: Passive Anticheat
- Quality of Life: Duel Reset, Skip DK, Auto Learn Spells, Reagent Bank, World Chat, Boss Announcer, Welcome Login
- Scripting Engine: Eluna Lua Engine, Eluna Script Collections
- Custom Content: World Bosses, Exchange NPC, Mythic+, Hardcore, RAF, Crime Bounty, Battle Pass, Paragon
- Legion-Specific: LegionCore Reforged, SylvaniaCore, Nordrassil Core

Моды разделены на две категории:

- **Нативный 26124** — реализация уже находится в `custom/src/`, автоматически копируется в дерево ядра и компилируется вместе с сервером.
- **Справочные** — остальные 38 модов зарегистрованы в каталоге как полезные дополнения, но требуют ручного копирования и портировки под TrinityCore/LegionCore. - **В ядре** — аналогичная функциональность уже присутствует в исходном LegionCore-7.3.5V2 и повторно не дублируется.
- **Справка** — альтернативное ядро или исследовательский источник, который нельзя смешивать с выбранным ядром 26124.

**Важно:** AzerothCore-моды используют API, отличный от TrinityCore. Курируемые моды копируются в папку интеграции, но могут потребовать адаптации под конкретную ревизию ядра перед компиляцией. Если мод не компилируется — удалите его папку из `server/source/src/server/scripts/Custom/IntegratedMods/` и пересоберите.

Каждый мод имеет ссылку на GitHub-репозиторий и метку совместимости: `stable`, `experimental`, `requires-porting` или `untested`. При переключении мода он сохраняется в PostgreSQL.

## Внутриигровой магазин (окно BattlePay, кнопка W)

Вкладка **«Магазин»** — редактируемый список товаров:

- карточки категорий фильтруют список («Открыть каталог»), есть поиск по названию и ID, фильтр по статусу и сортировка по цене и названию;
- **Добавить товар** — форма с категорией, типом выдачи, ID предмета, количеством, ценой, классом и порядком;
- карандаш — редактирование прямо в строке, корзина — удаление с подтверждением, переключатель — показать или скрыть товар в магазине;
- ID предмета ведёт на Wowhead для быстрой проверки.

Стартовый каталог — **172 товара**: 53 трансмога (легендарное оружие, редкие доспехи и плащи, которые сложно добыть), 39 маунтов, 12 питомцев, 6 игрушек, 6 услуг (имя, внешность, раса, фракция, гильдия, повышение уровня — выключено по умолчанию), **44 тома забытых способностей** с привязкой к классу, 10 товаров ускорения прогресса (наследуемые вещи, сумки) и 2 реагента улучшения. Каталог создаётся один раз: удалённые товары не возвращаются.

**Экспорт SQL** выгружает файл `battlepay_shop.sql` для таблиц LegionCore-7.3.5V2: `battlepay_product`, `battlepay_product_item`, `battlepay_shop_entry`, `battlepay_product_group`, `battlepay_display_info` и их `ruRU`-локали. Названия таблиц и столбцов взяты из загрузчика ядра `BattlePayData.cpp`. Заменяются только резервные строки (товары 900000–999999, группы 901–999), данные ядра не затрагиваются.

```text
mariadb --host=127.0.0.1 --port=3307 -u legion -p legion_world < battlepay_shop.sql
```

Затем в игре от администратора: `.battlepay reload`.

Ограничения:

- товары без ID предмета (тома способностей, реагенты улучшения) хранятся в каталоге, но в экспорт не попадают, пока для них не создан предмет;
- ядро LegionCore-7.3.5V2 списывает оплату в окне магазина с баланса доната аккаунта (`Player::GetDonateTokens` в `BattlePayHandler.cpp`), а не игровой валютой. Чтобы оплата шла Сущностями пробуждения, нужен патч BattlePay в ядре.

Валюта проекта — **Сущность пробуждения, ID 1533** (Wakening Essence, на неё покупаются и улучшаются легендарки Legion). Ранее в панели ошибочно стоял ID 1220 — это «Ресурсы оплота»; сохранённые настройки переводятся на 1533 автоматически.

## 60 мировых мини-боссов

Вкладка **«Мировые боссы»** в панели — это полнофункциональный редактор с 60 мировыми мини-боссами, распределенными по 7 континентам (Восточные королевства, Калимдор, Запределье, Нордскол, Пандария, Дренор, Расколотые острова):

- **Полное управление:** добавление нового босса через форму, редактирование любых параметров (имя, ID, зона, континент, уровень, сложность, время респавна, механика боя, координаты X/Y/Z, гарантированный и редкий лут), удаление и переключение активности.
- **Принцип лута:**
  1. *Гарантированный дроп (100%)* — 1000 единиц профессионального сырья (кожа, руда, ткань, травы, камни, частицы стихий), которое долго и тяжело фармить в открытом мире.
  2. *Редкий дроп (0.5%–3%)* — уникальный предмет: редкий трансмог, уникальный маунт, боевой питомец или реагент цепочки улучшения экипировки до 1000/1200 ilvl.
  3. Особый босс на Расколотом берегу — **«Пробуждённый Страж Пустоты»** (джекпот x25 Сущностей Пробуждения + маунт Морок Пустоты).
- **Экспорт SQL:** кнопка «Экспорт world_bosses.sql» генерирует полный дамп `creature_template` и `creature_loot_template` для всех 60 боссов (диапазон ID 900001–900070). Файл также сохранен в `custom/sql/world_bosses.sql`.

## Центр управления кастомными модулями

Вкладка **«Модули»** позволяет детально настраивать каждый из 8 кастомных компонентов без ручной правки кода ядра:
1. **Бонус за онлайн:** сумма награды (50), интервал (60 мин), ID валюты (1533), проверка AFK, минимальный уровень и текст системного оповещения.
2. **Улучшение экипировки:** шаг прокачки легендарок (+5), лимит 1200 ilvl (Концентрат силы #950030), эндгейм-вещи 985→1000 ilvl (Эссенция закалки #950031), стоимость 800 Сущностей, сохранение сокетов Легиона.
3. **Забытые способности:** NPC-наставник (#900100), цена тома (5000), строгая проверка класса, интерактивный список возвращаемых способностей с добавлением/удалением (Метаморфоза демонолога, Темная душа, Аспект стаи, Раскаленный доспех, Печать правды и др.).
4. **Система ИИ-ботов (Playerbot AI):** размер пула (128), автоприем в группу лидером, ассист в бою, контроль, автозаполнение пустых слотов на Аренах и БГ, интервал фраз в чат (120–240 с), редактируемый пул русских имен (80+ имен с возможностью добавления своих).
5. **Обработка битых квестов:** автозавершение при принятии, системное уведомление игрока, компенсация Сущностями, интерактивный менеджер ID квестов (добавление, удаление, примечания).
6. **Свободный трансмог:** снятие ограничений на типы брони (паладин в латах может трансмогрифицировать ткань/кожу/кольчугу), трансмог любого оружия, легендарных предметов, множитель стоимости.
7. **Внутриигровой магазин (BattlePay W-Key):** режим валюты 1533, открытие по кнопке W, баннер и услуги.
8. **Мировые боссы:** динамическое масштабирование здоровья/урона под число игроков в группе, анонсы спавна и победы в мировой чат.

## Чистая дельта

`server/source` — ваши исходники, их можно менять как угодно. Изменения кита
изолированы и повторяемы (оригиналы заменяемых файлов лежат в
`runtime/backups/source-originals/`):

- **C++ скрипты** — в `custom/src/` (см. `custom/src/README_RU.md`). Это готовая
  чистая дельта относительно апстрима: томы способностей, реагенты улучшения,
  торговец, бонус за онлайн, компенсация квестов, ИИ боссов. Интеграция в ядро —
  один обратимый шаг (копирование в `src/server/scripts/Custom/` + вызов
  `AddSC_LegionForge_Custom()`), поэтому штатная сборка остаётся зелёной.
- **SQL** — `custom/sql/custom_database.sql` (предметы, торговец, томы, реагенты)
  и `custom/sql/world_bosses.sql` (60 боссов). Плюс `battlepay_shop.sql` —
  экспорт магазина из панели.
- **Накладной слой** `patches/overlay/` применяется robocopy без удаления
  файлов базового ядра.
